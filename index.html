Puzzle Generator owldoku.com ↗

Owldoku

Sudoku-style puzzle game, custom ruleset

Built around a constraint-satisfaction generator. The "No Lines" mode layers a diagonal-exclusivity rule on top of standard placement constraints — getting a solvable, well-formed board out of that meant generating and validating millions of candidates through backtracking search.

  • Shared puzzles arrive as user-controlled URL codes, parsed through a dedicated validator and never trusted or rendered directly.
  • Screenshot/share feature clones the result card off-screen and re-namespaces SVG IDs to avoid collisions with the live page.
  • Best times and onboarding state persist through a defensively-wrapped storage layer that degrades gracefully on failure.
  • ResizeObserver-driven board sizing with pointer-event handling for consistent behavior across devices.
Game Engine rethy11.github.io/Slime-Sliders ↗

Slime Sliders

~10,000-line single-file game engine

Canvas rendering, custom physics, and procedural level generation, shipped solo from domain registration through Terms of Service authorship and ad-network integration.

  • Spatial hash grids handle collision detection for trees, fences, and terrain — near-constant-time lookups instead of naive all-pairs checks.
  • A storage wrapper with an in-memory fallback keeps the game running when localStorage is blocked or unavailable.
  • Currency and state writes are batched and throttled rather than fired on every event, avoiding synchronous-write frame stalls.
  • A crossfading audio state machine uses token-based cancellation to prevent race conditions between overlapping transitions.
Auth / 2FA rethy11.github.io/phone-verif ↗

Access

Firebase Phone Authentication (SMS OTP) + reCAPTCHA

A password-and-phone-gated landing page wired to a real SMS one-time-passcode flow through Firebase's modular SDK, with an invisible reCAPTCHA and a four-step UI state machine (password → phone → code → granted).

  • Phone ownership is verified server-side by Firebase via the SMS code — a genuine second factor, not a local check.
  • A capture-phase listener runs the phone-allowlist check before reCAPTCHA's own bubble-phase handler, so an unlisted number never triggers a real, billable challenge.
  • Failed sign-in attempts surface Firebase's actual error and cleanly reset the reCAPTCHA widget for a fresh attempt.
// engineering note

The password check and phone allowlist run entirely client-side — viewing source reveals both. That's a described limitation, not a claimed access-control boundary. The SMS verification itself is genuinely enforced server-side by Firebase.

Diagnostics / Instrumentation rethy11.github.io/Load-Watt ↗

Load-Watt

Browser performance & power-diagnostics tool

Built because nothing off-the-shelf could pinpoint what was draining battery or causing jank in the other projects. Runtime instrumentation and sandboxing rather than game logic.

  • Wraps every timer callback, DOM listener, and top-level function in a target file with timing shims — an aspect-oriented profiler injected at runtime.
  • Target code runs inside a sandboxed same-origin iframe; the tool snapshots the baseline global namespace and diffs it afterward to see what the code introduced.
  • Pulls repo structure from the GitHub API and explicitly surfaces rate-limit headers with an actionable error instead of failing silently.
  • Computes Total Blocking Time, dropped-frame rate, and main-thread-busy percentage, exported as a structured JSON report.
  • Run against Owldoku's own codebase, it found and fixed the source of battery drain — from roughly 1% per 30 seconds to 1% per 10 minutes on mobile.
Utility rethy11.github.io/Slopless ↗

Slopless

Minimal, fast search redirector

Smaller in scope, but a clean example of privacy-conscious front-end fundamentals — the entire client-side footprint is a search form and an ambient background animation.

  • No analytics, telemetry, or third-party data collection anywhere in the code — the privacy stance is enforced by what's (and isn't) there.
  • Detects iOS Safari versus the Chrome app and launches queries directly into Chrome via its custom URL scheme, falling back to a standard new tab elsewhere.
  • A cursor-reactive canvas animation respects prefers-reduced-motion and disables fully for users who need that.
  • Screen-reader-visible form labels, visible focus states, and a semantic, keyboard-submittable form.
